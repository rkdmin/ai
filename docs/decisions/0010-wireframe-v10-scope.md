# 0010 — 와이어프레임을 v1.0 으로 채택

## 배경

ADR 0001 은 "광고·잠금 없는 무료 Android 앱"을 v1.0 으로, ADR 0007 은 "v1.1 에서 광고 + 카드 잠금"을
수익화로 정했다. 그 뒤 Figma 에 **다른 제품**의 와이어프레임이 그려졌다
([plan 0009](../plans/0009-wireframe-review.md)). 홈·탭 4개·무료 무드 결과·유료 통합 리포트·STYLE 피드·
친구 케미·Guest-first 진입으로, 기존 v1.0 과는 화면 흐름과 수익 모델이 모두 다르다.

두 방향을 같이 둘 수는 없다. 기존 v1.0 을 먼저 내면 홈·탭·결과 화면을 두 번 만들고, 무료로 받은
사용자에게 나중에 유료 리포트를 설명해야 한다. 와이어프레임을 v1.0 으로 삼으면 출시는 늦어지지만
화면을 한 번만 만든다. 기존 v1.0 의 남은 작업은 운영 설정(`.aab`, Play 제출, Supabase 콘솔) 위주라
"거의 다 됐으니 내자"는 유혹이 있었으나, 출시 후 사용자가 보는 앱과 와이어프레임 앱이 다른 제품이라는
점이 결정적이었다.

Figma 자체는 아직 닫히지 않았다. 표시 화면 51개 중 23개에 미확정 텍스트 81개, 버튼 260개 중 164개는
목적지 근거가 없고, prototype 연결은 0개다. 그래서 **Figma 가 답한 것만 여기서 결정하고, 비워 둔 것은
UX 프로토타입을 본 뒤 별도 ADR 로 남긴다.** 근거 원문은
[Figma 재확인](../plans/0009-figma-recheck.md) Q1~Q7 에 노드 ID 와 함께 있다.

## 결정

### 1. 와이어프레임이 v1.0 이다 (R00)

ADR 0001 의 v1.0 범위와 ADR 0007 의 광고·카드 잠금 수익화를 **대체**한다.
살아남는 기반: 백엔드 분석(MediaPipe + Gemini), RAG, Supabase 인증, Capacitor 브리지, Beaumi 디자인 토큰.
버리는 것: 온보딩→로그인→분석 진입, 카드 4장 UI, 광고 게이트(`AdGate`), rank 잠금 정책.
Android 먼저·iOS 후속(ADR 0006·0008)은 유지한다.

### 2. 리포트는 구매 시점의 분석에 고정된다 (R01)

리포트 = 구매 당시 분석 snapshot + Hair + Makeup. 새 사진으로 재분석하면 무료 프로필(홈·STYLE·케미)만
바뀌고 리포트는 그대로다. 새 리포트는 다시 산다.

- Figma 원문: "사용자당 1개 통합 Beauty Report 보유", "중간 목록 화면 불필요",
  "향후 다수 Report 보관 시 Library 추가 가능", "분석 기록은 최대 10회까지 보관됩니다."
- 기록 정리(10회 초과)에서 **리포트가 붙은 분석은 지우지 않는다.** 지우면 리포트의 근거가 사라진다.
- 기록 행에 "리포트 있음" 표시는 Figma 에 없다. 구현 때 배지로 제안한다.

### 3. 가격은 앱에 적지 않는다 (R03)

가격·할인은 스토어 상품 metadata 를 받아 표시한다. 할인은 스토어가 할인 정보를 줄 때만 보여주고,
근거가 없으면 원가·할인율을 숨긴다. Figma 의 29,000/9,900 은 확정 표시가 없고 "[할인 TBD]" 뿐이라
운영값으로 쓰지 않는다. 실제 판매가는 Play Console 등록 때 정한다.

### 4. Android 결제 먼저 (R04)

결제 화면이 Android 하나뿐이다. 웹은 분석·초대 참여만 하고 결제하지 않는다. 웹 결제·iOS 는 별도 결정.

### 5. Primary 는 기존 무드 8개, Traits 는 별도 사전 (R06)

화면이 "Primary SOFT · Traits [곡선 윤곽] · [저대비]" 형태다. Primary 는 ADR 0001·0009 의 무드
아키타입 8개(`ROMANTIC / CLEAN / SOFT / ELEGANT / SHARP / CLASSIC / FRESH / EDGY`)를 그대로 쓴다.
Traits 는 구조·대비·질감을 말하는 **다른 사전**이고 0~2개다. 기존 무드 3개 배열을 계층으로 재배열해
Traits 로 쓰지 않는다. 그건 새 의미를 검증 없이 만드는 것이다.

## 미결 — UX 프로토타입 후 별도 ADR

| 항목 | Figma 상태 | 기운 쪽 |
|---|---|---|
| R02 게스트 결제 | "Guest-first / 저장·복원·Room 영구화 시 연결" — **구매는 열거되지 않음.** 결제 전 로그인 선 없음 | 결제 전 로그인 필수 |
| R05 복원·계정 충돌 | 관련 문구 0개 | R02 에 종속 |
| Room 생성 로그인 | 친구 초대 → 공유 시트 선·메모 없음 | R02 와 같은 규칙 |

이 셋은 코드 구조(소유자 컬럼, 복원 경로, 초대 흐름)를 바꾸므로 프로토타입에서 두 흐름을 눌러 본 뒤 정한다.
그때까지 P1 스키마의 소유자 컬럼은 추상화해 둔다.

## 근거

- **화면을 한 번만 만든다.** B(기존 v1.0 선출시)의 유일한 장점은 빠른 실사용 지표였고, 그 대가가 홈·탭·결과
  화면 재작성과 무료→유료 전환 설명이었다.
- **Figma 가 답한 것만 결정했다.** R02 는 Figma 와 충돌하지 않는 선택이 둘 다 가능해 보류했다.
  추측으로 채운 결정은 나중에 Figma 와 어긋나면 되돌리는 비용이 더 크다.
- **리포트 고정(R01)은 Figma 의 모양 그 자체다.** 리포트 화면이 하나, 기록 행에 구매 버튼 없음,
  "향후 Library" 메모. 평생 재생성은 나중에 "재생성권"으로 확장할 수 있어 지금 닫아도 잃는 게 없다.
