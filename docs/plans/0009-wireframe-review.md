## 기준과 확인 범위

- 기준: [뷰티 app 맨 오른쪽 최신 캔버스](https://www.figma.com/design/PCUCRGz6FRNmOrhynuHulp?node-id=108-2562).
- 최신 캔버스 내 표시 프레임 52개와 숨김 2개를 구분했습니다. 긴 버전·중복·상태 프레임이 포함되므로 52개의 독립 페이지를 의미하지 않습니다.
- 피그마 MCP로 전체 구조, 주요 화면의 실제 텍스트와 IA 주석, 캔버스 이미지를 확인하고 저장소 코드·문서와 대조했습니다.
- 추가 MCP 호출 한도로 일부 STYLE·MY·초대 화면은 메타데이터/레이어 이름 근거를 포함합니다. 실제 카피·목적지 재확인 항목은 보고서 02·12절에 별도 표시했습니다.
- 실제 배포 서버·DB 설정·스토어 계정·결제 준비 상태는 이번 소스 검토만으로 확인하지 않았습니다.
- [프레임 근거 목록 JSON](./0009-wireframe-inventory.json)과 보고서 12절에서 개별 Figma 노드를 다시 열 수 있습니다.

## 핵심 분류

| 분류 | 주요 변경 |
|---|---|
| 새 기능 | Guest-first 프로필, 유료 Hair+Makeup 리포트·구매/복원, STYLE 피드·상세·북마크, 케미 Room·랭킹·초대 웹/앱 인계, 계정 병합·실제 삭제 |
| 데이터·계약 | 기존 8개 무드 키 재사용 검토, primary/traits와 근거 저장, 상세 헤어/메이크업 RAG 확장, 리포트 snapshot·구매 권한·Room·북마크 신규 구조, 사진 보관·캐시 정책 |
| UI/UX 조건부 | 탭·목록·상세 레이아웃, 무료 결과 카드, 촬영 안내, 로딩·오류·복원 상태 표현. 서버 검증·실제 데이터·목적지 기능이 필요한 부분은 UI-only로 분류하지 않음 |

현재 카드는 매퍼상 모두 `locked=false`이고, 기존 `/api/cards/total`은 새 구매형 통합 리포트가 아닙니다.
MY 계정 삭제는 서버 삭제가 아니며, 사진 폐기 안내와 90일 만료 메타데이터도 일치하지 않습니다.
이런 항목은 겉모양 변경 전에 제품 정책·권한·데이터 수명주기를 결정해야 합니다.

## 권장 검토 순서

1. 보고서 **01·03절**: 목표 흐름과 화면별 분류가 의도와 맞는지 확인.
2. **10절 R01~R08**: 재분석/리포트 소유권, 게스트 신원, 가격·판매 단위, 플랫폼/결제, 복원 소유권, 무드·traits, 케미 계산, 설치 후 인계 방식을 먼저 결정.
3. **04·05절**: 기능 12개 묶음과 데이터·API 제안의 누락/과잉 범위 확인.
4. **10절 나머지 결정**: 저장 의미·이력·TRY ON·설정·기존 사용자·사진 보관·Room 갱신·출시 범위 확정.
5. **08·09·11절**: 단계·품질 게이트·문서/운영 작업을 검토한 뒤 새 ADR과 실행 작업으로 분해.

## 공수 읽는 법

전체 제안은 P0~P8 기준 **54~93 인일**, 기반·분석·리포트와 해당 QA는 **34~58 인일**입니다.
이는 정책 확정 전의 1인 엔지니어 기준 추정 범위이며 출시 일정 약속이 아닙니다.
외부 콘텐츠 제작, 결제/계정 설정 대기, 스토어 심사 등은 따로 봐야 합니다.
확정된 범위·운영 데이터·POC 결과로 단계 시작 전에 다시 산정합니다.

## 문서 상태

이 문서는 현재 구현의 단일 진실 소스가 아니라 **승인을 기다리는 계획**입니다.
기존 Accepted ADR은 수정하지 않았습니다. 승인 후 새 ADR로 대체 관계를 기록하고,
실제 구현과 같은 작업에서 `ui-flow`, API 계약, 연결 현황, RAG 가이드, 테스트, 로드맵을 갱신합니다.
